# UQRA 兼容自适应稀疏 PCE：后续开发计划

## 1. 文档目的

本文档规定 `uqra.adaptive` 初版实现完成后的验证、集成和发布顺序。目标是把当前的兼容机制实现推进为可审计、可重复、可用于论文实验的 UQRA 兼容自适应稀疏 PCE 实现。

本文档服从以下权威材料：

1. `UQRA_COMPATIBILITY_DECISIONS.md` 中的算法裁决；
2. `SOURCE_CORRECTION_HANDOFF.md` 中的实施边界和验收要求；
3. canonical UQRA 源码及博士论文中的数学定义；
4. 经明确预注册的投稿实验协议。

当前实现分支为 `agent/adaptive-pce-compatibility`，初版提交为 `4c9a9e8653fdb07272f8ddb4ca62a50b7050432e`。

## 2. 当前基线

已经完成：

- 冻结候选池、稳定全局样本 ID 和跨阶累积观测；
- 坐标哈希、重复真实模型调用保护及运行时不变量；
- DoI 局部行号到全局 ID 的显式映射；
- legacy-compatible 权重与标准化接口；
- 真正的 LARS 进入路径、确定性路径 CV 和活跃基 OLS 重拟合；
- RRQR 初始化及 UQRA D/S-optimal 评分框架；
- `literal_legacy`、`dissertation` 和 `publication` 兼容配置；
- 外层收敛、最高阶非收敛及一次性过拟合降阶重建状态；
- 小型二维确定性 fixture、输入哈希和追踪哈希；
- 10 项兼容性自动化测试。

阶段更新（2026-08-04）：阶段 5 的控制器状态机审查和补强已经完成；阶段 6 的首个真实 canonical `uqra.Hermite` fixture 已通过。兼容性测试现为 20 项。详细证据见 `ADAPTIVE_PCE_PHASE5_AUDIT_SUMMARY.md`。

当前声明边界：现阶段只能声明兼容机制和核心不变量已经通过小型 fixture 验证。历史大型候选池和测试集尚未恢复，因此不得声明已复现博士论文四分支最终数值结果。

## 3. 阶段 5：实现审查与状态机补强

**状态：已完成。**

### 3.1 工作内容

1. 审查双层控制器是否完整实现多轮内循环，而不是只执行一轮全局增广和 DoI 增广；
2. 明确每种兼容配置的阶内预算、QoI 稳定次数、批次截断和无可用候选时的行为；
3. 为以下投稿状态机路径增加定向测试：
   - 正常外层收敛；
   - 达到最高阶但未收敛；
   - 连续三阶 CV 上升触发过拟合；
   - 唯一一次降阶重建后收敛；
   - 有限但未收敛的 `overfit_fallback`；
   - 主路径和重建路径均无有效模型的 `runtime_failure`；
4. 检查重建模型是否保留高阶阶段新增的全部真实观测；
5. 验证所有终止出口均记录有限枚举的 `stop_reason`。

### 3.2 验收门槛

- 每条终止路径至少有一个自动化测试；
- 多轮内循环的新增样本、重拟合次数和 QoI 历史可在 trace 中逐轮恢复；
- 降阶重建最多执行一次，且不会形成回退循环；
- 所有样本身份不变量在每轮增广后均成立；
- 审查完成前不得把当前分支标记为可合并的投稿实现。

## 4. 阶段 6：真实 UQRA Hermite 基验证

**状态：首个真实二维 fixture 已完成；更大规模及 legacy 对照并入阶段 7。**

### 4.1 工作内容

1. 使用 `uqra.Hermite.vandermonde` 替换测试中的 Hermite-like 单项式 fixture；
2. 固定二维候选池、测试集、随机数生成器和全部随机种子；
3. 记录真实 Hermite 多指标排序及归一化约定；
4. 对以下数组逐元素比较并记录浮点容差：
   - 完整 Vandermonde；
   - 采样权重；
   - 中心化和标准化后的设计矩阵；
   - 加权响应；
5. 重复运行并确认候选池、测试集及完整 trace 哈希稳定。

### 4.2 验收门槛

- fixture 直接调用 canonical UQRA 多项式类；
- 多指标顺序和 Vandermonde 数值具有固定基准；
- 权重及预处理数组在声明容差内逐元素一致；
- 相同环境和输入重复运行时 trace hash 完全一致。

## 5. 阶段 7：legacy 与现代内核逐轮行为回归

**状态：首轮冻结 Hermite 行为回归已完成。**

阶段结果（2026-08-04）：权重和预处理逐元素一致；LARS 进入路径、固定 fold、CV 路径和截断位置一致；RRQR 初始 ID 一致；D/S 三轮全候选分数在 `2e-12` 容差内一致且每轮选中 ID 相同；DoI 候选集合和现代局部/全局映射已固定；IDX-01/IDX-02 差异被确认并分类为已裁决的 legacy 缺陷修正。详细证据见 `ADAPTIVE_PCE_PHASE7_REGRESSION_SUMMARY.md`。

### 5.1 比较顺序

按照以下顺序建立 legacy 与现代追踪，不得只比较最终 QoI：

1. 基排序和 Vandermonde 数值；
2. 权重和预处理数组；
3. LARS 基函数进入顺序；
4. 路径 CV、并列处理和选定前缀；
5. RRQR 初始索引；
6. 每个 D/S 候选分数和选定全局 ID；
7. DoI 中心、全局候选集合及局部到全局映射；
8. 每轮累积已评估 ID、坐标哈希和模型调用数；
9. 阶内和阶间 QoI 序列；
10. 内外循环停止位置、最终状态和停止原因。

### 5.2 差异分类

每项差异必须归入以下一类，并附证据：

- 已裁决的 legacy 源码缺陷修正；
- 依赖版本造成且位于声明容差内的浮点差异；
- 兼容配置有意造成的行为差异；
- 尚未解释、必须阻止合并的算法差异。

### 5.3 验收门槛

- LARS、CV、RRQR、D/S 评分及 DoI 映射均有中间状态基准；
- 所有有意差异均能追溯到具名兼容配置或算法裁决；
- 不存在未解释的样本 ID、选点或模型调用差异；
- 最终失效概率接近不得作为中间行为不一致的豁免理由。

## 6. 阶段 8：确定性 benchmark 端到端集成

**状态：已完成。**

阶段结果（2026-08-04）：已建立二维 deterministic Hermite benchmark 和 `python -m uqra.adaptive.benchmark` manifest 命令；正常收敛、最高阶非收敛、过拟合回退和运行失败四类场景均已固定；前三类完整经过全局与 DoI 增广；所有场景通过样本身份不变量；重复运行 manifest 和 trace 哈希一致。详细证据见 `ADAPTIVE_PCE_PHASE8_BENCHMARK_SUMMARY.md`。

### 6.1 工作内容

1. 选择计算成本低且确定性的二维 benchmark；
2. 执行完整的升阶、全局增广、重拟合、DoI 增广和停止流程；
3. 覆盖正常收敛、最高阶非收敛、过拟合回退和运行失败场景；
4. 输出包含以下字段的结果 manifest：
   - Git 提交和工作树状态；
   - 兼容配置；
   - Python 及依赖版本；
   - 所有随机种子和 RNG 类型；
   - 候选池、测试集和 trace 哈希；
   - 运行命令；
   - 唯一真实模型调用数；
   - 最终状态和 `stop_reason`。

### 6.2 验收门槛

- `model_call_count == len(evaluated_coordinate_hashes)`；
- 不存在重复坐标评估；
- 每个新增样本在选择前均属于未评估集合；
- 多次运行得到一致的 trace 和结果 manifest；
- benchmark 可由一条记录完整的命令重现。

## 7. 阶段 9：历史实验数据恢复与四分支追踪

**状态：恢复审计和可执行诊断已完成；canonical 历史复现因原始外部数据缺失而不可用。**

### 7.1 数据目标

寻找并恢复博士论文实验使用的：

- 约 $10^5$ 规模的候选池；
- 约 $10^6$ 规模的测试或预测集；
- 四分支模型输入、归档输出和运行脚本；
- 候选抽样、CV shuffle 及其他随机操作的历史状态或种子。

### 7.2 恢复要求

- 原始文件只读保存；
- 为每个数据文件记录 SHA-256、形状、数据类型和来源；
- 无法恢复的输入明确标记为 unavailable，不得用新生成数据冒充历史输入；
- legacy 追踪必须保留已知 IDX-01/IDX-02 字面行为，以用于诊断影响范围。

> 阶段结果（2026-08-04）：已只读搜索 G:/F: 历史归档，登记相关 10×10⁶ MCS 数组和四分支汇总结果的来源、形状、dtype 与 SHA-256；canonical 10⁵ 候选池、四分支 10⁶ 测试集、逐轮结果及 RNG/CV 状态均标为 unavailable。已在恢复的历史正态坐标上执行确定性源码语义诊断：IDX-01 导致 66/66 个跨阶身份错配、66 个错误排除并漏排 5 个已观测坐标；IDX-02 导致 32/32 个 DoI 身份错配；现代稳定-ID对应计数均为 0。该结果明确不是缺失历史随机状态的重建，详见 `ADAPTIVE_PCE_PHASE9_HISTORY_RECOVERY_SUMMARY.md`。

### 7.3 验收门槛

- 历史输入身份可验证；
- 能回答历史结果是否受到跨阶索引和 DoI 索引缺陷影响；
- 在完成逐轮行为解释前，不得仅凭最终 Pf 接近宣称数值等价。

## 8. 阶段 10：依赖和持续集成现代化

**状态：已完成。**

### 8.1 工作内容

1. 处理 `pyDOE2` 在 Python 3.12 中使用已删除 `imp` 模块的问题；
2. 清理 `setup.py` 中重复、过时或名称不规范的依赖声明；
3. 锁定 NumPy、SciPy、scikit-learn 和 pytest 的验证版本；
4. 保留 legacy `normalize` 的数学等价预处理测试；
5. 建立至少覆盖 Python 3.11 和投稿目标环境的 CI；
6. 将兼容性测试作为合并必需检查。

许可证元数据与仓库 `LICENSE` 的不一致必须单独核实，不在算法修改中擅自改写。

### 8.2 验收门槛

- 从干净环境可安装并运行兼容性测试；
- CI 可重复执行真实 Hermite fixture 和端到端 benchmark；
- 不依赖临时 `PYTHONPATH` 或手动安装未声明依赖；
- Python 版本边界和弃用依赖均在安装文档中明确记录。

> 阶段结果（2026-08-04）：已用内部兼容 LHS 实现移除 `pyDOE2` 及其 `imp` 导入路径；清理 `sklearn` 重复占位依赖并添加 Python 3.11/3.12 精确锁；在全新 Python 3.11.15 venv 中无需临时 `PYTHONPATH` 完成安装并通过 35 项兼容性测试；CI 建立 Python 3.11/投稿目标 3.12 矩阵，并由稳定的 `Adaptive compatibility gate` 聚合阶段 6--9 明确门槛与完整兼容性套件。详见 `ADAPTIVE_PCE_PHASE10_ENVIRONMENT_CI_SUMMARY.md`。

## 9. 阶段 11：投稿实验与合并发布

**状态：投稿协议、低成本敏感性实验、最终审查与合并准备已完成。**

只有阶段 5--10 的验收门槛全部满足后，才进入投稿实验：

1. 冻结 `publication` 配置和实验协议；
2. 预注册预算、DoI 回退、CV、外层稳定次数和 accuracy/validity 条件；
3. 执行敏感性分析并单独统计 `overfit_fallback`；
4. 区分 canonical UQRA、现代兼容实现和 portable 对照结果；
5. 完成代码审查和行为回归报告后合并到默认分支；
6. 以提交哈希、输入哈希和 manifest 作为论文结果的复现入口。

> 阶段结果（2026-08-04）：已冻结 publication 输入、配置、预算、DoI、CV、外层稳定和 accuracy/validity 条件；现代与 portable 实现分别完成 11 组敏感性实验，全部样本身份不变量通过且逐轮 trace 一致；两组各 1 个 `overfit_fallback` 已独立统计；canonical 历史结果继续明确为 unavailable。最终代码审查发现的冻结对象可变性、回退 final QoI 和源码身份记录问题均已修正，修正后无未解决 P0--P3 发现。详见 `ADAPTIVE_PCE_PHASE11_PUBLICATION_RELEASE_SUMMARY.md`。

## 10. 优先级与依赖关系

执行顺序固定为：

```text
阶段 5：实现审查与状态机补强
  -> 阶段 6：真实 Hermite 基验证
  -> 阶段 7：legacy/现代逐轮回归
  -> 阶段 8：确定性 benchmark 集成
  -> 阶段 9：历史数据恢复与四分支追踪
  -> 阶段 10：环境与 CI 固化
  -> 阶段 11：投稿实验与合并发布
```

阶段 9 的外部数据恢复可以与阶段 5--8 并行准备，但不得绕过阶段 7 的中间行为验证。当前最高优先级是阶段 5、6 和 7；三者完成前，当前实现应保持为待审查兼容分支。
