# UQRA 博士论文数值与科学结论复现计划

## 1. 目的与结论边界

本文档规定在原始历史候选池、测试集、逐轮结果和随机状态已经确认不可恢复的前提下，如何重新执行博士论文实验，验证论文的数值规律与科学结论。

本工作属于 **计算性重现（computational reproduction）**，不是历史结果重放。所有输入均重新生成并记录随机种子、数据形状、数据类型和 SHA-256；任何新结果不得标记为 canonical 历史结果，也不得用与论文最终数值接近代替算法、实验协议和统计结论的验证。

复现目标按以下优先级验收：

1. 数学问题、概率模型、PCE 构造和自适应试验设计与论文定义一致；
2. 论文所报告的主要趋势、方法排序、收敛规律和结论在预注册容差内成立；
3. 关键数值表格和图中数据能够由固定命令重复生成；
4. 每项结论均能追溯到输入、配置、代码提交、manifest 和统计判据；
5. 原论文单次实现相关的末位数值、历史样本 ID 和历史随机轨迹不作为成功条件。

## 2. 已具备基线

以下能力直接复用，不重新实现：

- `UQRA_COMPATIBILITY_DECISIONS.md` 已冻结 `dissertation`、`publication` 和 `literal_legacy` 的边界；
- 阶段 5--7 已验证状态机、真实 `uqra.Hermite`、LARS/CV/OLS、RRQR、D/S 评分和 DoI 映射；
- 阶段 8 已提供确定性二维端到端 benchmark 和完整 trace；
- 阶段 9 已确认历史大型输入不可恢复，并禁止把新数据冒充历史输入；
- 阶段 10 已提供 Python 3.11/3.12 的安装锁和兼容性测试门槛；
- 阶段 11 已提供低成本 `publication` 协议、manifest、敏感性案例及唯一模型调用不变量。

当前阶段 11 benchmark 只证明实现机制可重复，尚不能代表博士论文中的完整问题规模、失效概率精度或全部科学结论。

## 3. 权威证据与冲突处理

每个实验定义按以下优先级取证：

1. 博士论文公式、算法、表格、图注和正文结论；
2. canonical UQRA 源码中与论文一致的数学实现；
3. 已裁决的 `UQRA_COMPATIBILITY_DECISIONS.md`；
4. 当前 `publication` 配置只作为缺失细节的现代对照，不得反推为论文事实；
5. legacy 脚本的 IDX-01/IDX-02 字面行为只用于诊断，不进入论文算法结果。

若论文没有给出随机种子、连续稳定次数、并列规则或精确容差，必须登记为 `unspecified_in_dissertation`，随后预注册现代确定性取值并执行敏感性分析。不得把补充取值写成历史事实。

## 4. 复现产物

最终应产生以下可版本控制的定义和报告：

- `specs/DISSERTATION_CLAIM_MATRIX.md`：逐章、逐表、逐图的科学结论与验收判据；
- `specs/DISSERTATION_EXPERIMENT_PROTOCOL.md`：问题定义、输入分布、模型、方法、预算、重复次数和统计方法；
- `specs/DISSERTATION_REPRODUCTION_REPORT.md`：最终结论、偏差解释、失败项和适用边界；
- `artifacts/dissertation/inputs/`：重新生成的冻结输入及清单；
- `artifacts/dissertation/runs/`：每次运行的 manifest、trace 和原始指标；
- `artifacts/dissertation/summary/`：聚合表格、置信区间和结论判定；
- 一条总入口命令和若干可恢复的分阶段命令。

大型数组和批量运行产物默认不提交 Git；Git 中保存生成器、schema、小型金标准 fixture、哈希清单和摘要。具体归档位置必须在执行前确定。

## 5. 固定实施顺序

### 阶段 R0：论文结论与实验清单冻结

1. 以论文 PDF 为权威来源，登记所有需要数值验证的章节、算法、表格和图片；
2. 对每项结论记录：原文位置、问题模型、维数、输入分布、QoI、对照方法、样本预算、重复次数和论文报告值；
3. 把结论分为：绝对数值、方法排序、收敛趋势、稳定性/鲁棒性、计算效率和失效概率精度；
4. 为每项结论定义 `pass`、`partial`、`fail`、`not_testable` 四种状态；
5. 明确哪些实验属于 FourBranch，哪些属于其他解析 benchmark 或工程模型。

验收门槛：论文中所有拟复现的数值结论都有唯一 ID；没有仅凭记忆补写的参数；所有缺失信息均显式登记。

### 阶段 R1：论文实验协议重建与预注册

1. 从论文和源码重建每个问题的数学定义、输入域映射、Hermite/Legendre 类型和归一化；
2. 冻结候选池与测试集生成方法、RNG 类型、主种子和重复试验派生种子；
3. 冻结 PCE 阶次范围、LARS/CV、D/S-optimal、DoI、预算和停止条件；
4. 冻结参照真值的获得方式：解析值、高精度积分或独立大规模 Monte Carlo；
5. 在看正式实验结果前预注册误差指标、容差、置信区间和结论判定规则。

FourBranch 至少记录：失效函数的符号约定、输入为独立标准正态、目标 `Pf`、预测样本规模、候选池规模、重复次数和每种 DoE 的真实模型调用预算。

验收门槛：协议可以在不读取论文结果数据的情况下生成全部输入和运行配置；协议哈希固定；`dissertation` 中未决参数没有被 `publication` 默认值静默替代。

### 阶段 R2：输入生成器和参照真值

1. 为每个 benchmark 实现确定性、可分块的输入生成器；
2. 采用稳定 schema 保存形状、dtype、分布、种子、生成器版本和 SHA-256；
3. 对候选池、测试集和真值集实施坐标身份及重复检查；
4. 对解析 benchmark 以解析值或独立实现验证真值；
5. 对稀有失效概率使用分块 Monte Carlo，报告二项抽样误差和有效样本量，必要时增加独立种子重复；
6. 禁止继续依赖 `Benchmark_postprocess.py` 中旧的绝对路径和未定义运行状态。

验收门槛：同一配置重复生成的输入哈希一致；真值估计达到预注册精度；生成和统计过程不依赖 pickle 对象数组或用户机器路径。

### 阶段 R3：小规模管线资格验证

1. 每个实验先以缩小候选池、测试集和预算完成一次全流程运行；
2. 验证 Vandermonde、权重、路径 CV、RRQR/OED、DoI、累计观测和停止位置；
3. 验证 `model_call_count == len(evaluated_coordinate_hashes)`；
4. 验证进程中断后的 checkpoint 恢复不会改变 trace 或重复调用模型；
5. 估算正式实验的时间、内存、磁盘和并发需求。

验收门槛：所有阶段 6--11 兼容性测试继续通过；每个论文实验至少有一个小型金标准 fixture；资源估算和失败恢复演练通过。

### 阶段 R4：FourBranch 正式数值复现

1. 先建立独立高精度 FourBranch 参照 `Pf` 及置信区间；
2. 按论文方法逐一运行 MCS/LHS、D-optimal、S-optimal、CLS 及自适应稀疏 PCE 中实际出现的对照组；
3. 对每种方法执行预注册数量的独立重复试验；
4. 每轮保存阶次、活跃基数、CV、RMSE、`Pf_hat`、相对误差、选点阶段、唯一模型调用数和停止原因；
5. `overfit_fallback`、`nonconverged` 和 `runtime_failure` 分开统计，不得从成功样本中静默删除；
6. 同时保留 modern-compatible 主结果和 portable 数值核对；`literal_legacy` 只在小规模诊断中运行。

验收门槛：每个方法的成功率、失败率、模型调用数分布和 `Pf` 误差区间齐全；全部身份不变量成立；同一 manifest 可恢复同一结果。

### 阶段 R5：其余论文 benchmark 与消融实验

1. 按 R0 清单顺序复现其余解析或工程 benchmark；
2. 在相同真实模型调用预算下比较方法，避免用不同计算成本制造排序；
3. 执行无 DoI、仅全局增广、D/S 切换、候选池规模、CV fold、阶次上限和停止阈值消融；
4. 对随机种子、候选池规模和参照集规模执行敏感性分析；
5. 工程模型若缺少外部求解器或输入文件，单独标记为 `not_testable`，不得由解析 benchmark 代替。

验收门槛：论文主结论不依赖单一种子或单个异常重复；消融能够解释方法改进来源；不可执行项有明确外部依赖清单。

### 阶段 R6：统计聚合与科学结论判定

1. 所有方法报告中位数、四分位区间、均值、标准差和预注册置信区间；
2. 失效概率同时报告绝对误差、相对误差和抽样不确定度；
3. 方法排序只有在重复试验和不确定度支持时才判为 reproduced；
4. 将每个 claim ID 判定为 `pass`、`partial`、`fail` 或 `not_testable`；
5. 对偏差区分：历史数据缺失、论文参数未指定、依赖版本、已修复 legacy 缺陷、统计波动和真实算法差异；
6. 禁止只展示最优重复或只比较最终 `Pf`。

验收门槛：每个科学结论都链接到机器可读指标；统计代码有测试；从原始 manifest 重新聚合得到相同摘要哈希。

### 阶段 R7：独立复跑与发布包

1. 在干净 Python 3.11 环境从零生成输入、执行至少一个完整重复并聚合结果；
2. 在 Python 3.12 运行兼容性门槛和小型金标准，不强制重复全部高成本实验；
3. 由独立进程或另一台机器验证总入口命令、checkpoint 和哈希；
4. 输出最终复现报告，明确哪些结论成功、部分成功、失败或不可测试；
5. 固定 Git 提交、依赖锁、协议哈希、输入清单哈希、结果摘要哈希和运行环境。

验收门槛：干净环境复跑成功；报告中的全部数值可以追溯；没有把 reconstructed 结果描述为历史原始结果。

## 6. 统一 manifest 最低字段

每次正式运行至少记录：

- claim ID、experiment ID、replicate ID 和实现类别；
- Git commit、源码树哈希、工作树状态和运行命令；
- Python、NumPy、SciPy、scikit-learn 和 UQRA 版本；
- 协议版本与协议哈希；
- RNG 类型、主种子、派生种子和 CV fold 身份；
- 候选池、测试集、真值集的形状、dtype 和 SHA-256；
- 完整兼容配置、预算、DoI、CV、停止和 accuracy/validity 条件；
- 每阶/每轮 trace、选中全局 ID、唯一坐标哈希和真实模型调用数；
- QoI、`Pf_hat`、RMSE、CV、score、活跃基数和计算时间；
- 状态、`stop_reason`、回退披露和全部不变量检查。

## 7. 科学结论判定原则

- **绝对数值**：重建结果的置信区间与论文报告值在预注册数值容差内相容；
- **方法排序**：在相同预算下，主要指标的方向和排序与论文一致，且不是由单个重复驱动；
- **收敛趋势**：随预算或阶次变化的方向一致，并报告非单调区间；
- **效率结论**：以唯一真实模型调用数为主，运行时间只作环境相关的补充指标；
- **稳健性结论**：跨种子、候选池和合理配置扰动后仍成立；
- **部分复现**：趋势成立但绝对值不相容，或只有部分 benchmark 支持；
- **不可测试**：缺少论文定义、外部求解器或不可替代的工程输入，不等同于失败。

最终门槛不要求逐位匹配历史数值，但要求所有差异都有可审计解释。

## 8. 资源与风险控制

主要风险及处理：

| 风险 | 处理 |
| --- | --- |
| 论文未提供完整实验细节 | 登记未决项，预注册现代取值并做敏感性分析 |
| 稀有事件真值需要超大样本 | 分块/流式计算、独立重复和置信区间，不把数组全部驻留内存 |
| 旧脚本依赖机器绝对路径 | 建立配置化入口和稳定数据 schema，不直接复活旧路径 |
| 长任务中断 | 原子 checkpoint、完成批次清单和幂等恢复 |
| 选择性报告 | 预注册全部方法、重复和失败状态，聚合时保留失败分母 |
| legacy 缺陷改变历史结果 | 主结果遵循 `dissertation` 数学裁决，字面 legacy 仅作诊断 |
| 计算成本超出资源 | 先资格验证和资源估算，再批准正式规模；不得静默缩小后仍称完整复现 |
